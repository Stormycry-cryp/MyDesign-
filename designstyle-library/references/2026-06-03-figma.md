# Style Reference: Figma

## Essence
A collaborative creative-tool style that balances product rigor with approachable color, modular examples, and community energy. The reusable idea is to make creation feel shared and alive without losing interface clarity.

## When To Use
- Design tools, whiteboards, AI creation products, collaborative editors, team brainstorming, education around workflows.
- Pages where multiple personas need to see themselves in the same product.
- Interfaces that can show cursors, comments, layers, components, and artifacts as visual language.

## When Not To Use
- Highly regulated finance/legal/medical workflows where playfulness harms trust.
- Solo luxury brand pages that need a single controlled voice.
- Dense enterprise admin tables where saturated color competes with status meaning.

## Visual System
- Layout: Modular sections showing creation artifacts, collaboration moments, feature blocks, and templates.
- Typography: Friendly modern sans, clear product copy, approachable headings with enough whitespace.
- Color: Broad but controlled palette; colorful accents map to creativity and collaboration, not random decoration.
- Density: Medium; artifact-rich but breathable.
- Shape: Rounded panels, cursor/comment chips, canvas-like surfaces.
- Shadow/depth: Light panel separation, canvas layering, soft shadows only when needed.

## Assets
- Image style: Real product canvases, prototypes, component libraries, comments, multiplayer cursors.
- Illustration/icon style: Simple geometric icons, colorful but systematized.
- Texture/pattern: Canvas grids, dotted backgrounds, sticky-note/board metaphors where relevant.
- Likely sources or production method: Product screenshots, template thumbnails, community examples, custom vector spots.

## Motion
- Page transitions: Light, friendly, not cinematic.
- Micro-interactions: Cursor movement, selection outlines, comment reveal, drag/drop feedback.
- Scroll/entrance behavior: Feature artifacts can animate into composition; keep it legible.
- Timing/easing: Medium, elastic only when it represents creation/play.

## Interaction And Components
- Navigation: Product/platform/community/enterprise paths must be distinct.
- Buttons/links: Friendly CTAs, often paired with product proof or template links.
- Cards/sections: Cards can look like canvases, files, templates, or collaboration objects.
- Forms/inputs: Invite/share/comment flows need clarity and trust.
- Feedback states: Presence, selection, comments, versioning, and activity states are part of the aesthetic.

## Implementation Notes
- CSS/layout primitives: Canvas surfaces, layered absolute artifacts, grid backgrounds, cursor/comment components.
- Token ideas: Collaboration colors, canvas background, file-card radius, comment-chip states.
- Libraries or techniques: Drag-and-drop libraries for real tools; motion for cursor/presence demos.
- Performance/accessibility concerns: Colorful UI needs semantic status colors; avoid relying on color alone.

## Borrow
- Use product artifacts as expressive visuals.
- Make collaboration states visible, not hidden in copy.
- Use color as a system for roles, objects, and creation modes.

## Avoid Copying
- Do not sprinkle random bright shapes to imitate creativity.
- Avoid fake cursors/comments that do not connect to an actual workflow.
- Do not force this warmth onto serious compliance-heavy products.
