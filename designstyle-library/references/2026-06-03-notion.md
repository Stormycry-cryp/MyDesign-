# Style Reference: Notion

## Essence
A warm productivity style that turns flexible workspace software into something approachable through editorial pacing, monochrome foundations, simple illustration, and modular content blocks. The reusable idea is calm capability.

## When To Use
- Knowledge bases, docs, project planning, lightweight CRM, AI workspace, community operating systems.
- Products that need to feel flexible and human rather than enterprise-heavy.
- Onboarding pages where users must understand many possible use cases without anxiety.

## When Not To Use
- Premium cinematic product launches that need visual spectacle.
- Hardcore developer platforms where code proof matters more than warmth.
- Dense task screens where cute illustration would waste space.

## Visual System
- Layout: Editorial sections, block-like modules, product examples, use-case grids, templates, and customer stories.
- Typography: Friendly sans with slightly bookish rhythm; headings are clear, not aggressive.
- Color: Off-white, black, grayscale, selective warm accents and illustration color.
- Density: Medium; calm spacing but enough examples to show flexibility.
- Shape: Soft rectangles, document blocks, checklist/database metaphors.
- Shadow/depth: Light paper-like separation, little dramatic elevation.

## Assets
- Image style: Document/workspace screenshots, database views, AI blocks, template previews.
- Illustration/icon style: Hand-drawn or simple editorial illustrations; monochrome line icons.
- Texture/pattern: Paper/document feel, subtle dividers, block outlines.
- Likely sources or production method: Product screenshots, custom editorial illustration, template thumbnails.

## Motion
- Page transitions: Minimal and friendly.
- Micro-interactions: Block insertion, hover menus, checkbox/database changes, AI typing indicators.
- Scroll/entrance behavior: Simple reveal; avoid heavy staging.
- Timing/easing: Gentle 150-250ms; motion should feel like editing a document.

## Interaction And Components
- Navigation: Use-case and product-family navigation should reduce the feeling of infinite flexibility.
- Buttons/links: Clear start/template CTAs; secondary links to examples.
- Cards/sections: Cards can be templates, docs, boards, or wiki pages.
- Forms/inputs: Search, slash-command, AI prompt, and invite fields are core.
- Feedback states: Empty templates, synced blocks, AI generation, permission states.

- Inference: modular blocks, template previews, and document-like surfaces map cleanly to reusable block components and CMS/product screenshot assets.
- Limit: authenticated workspace UI and exact public-page CSS were not inspected.

## Implementation Notes
- CSS/layout primitives: Block components, document-width containers, modular grids, subtle borders, template cards.
- Token ideas: Paper background, ink text, muted dividers, warm accent, block radius.
- Libraries or techniques: Rich text/editor primitives if building product; lightweight motion for block changes.
- Performance/accessibility concerns: Keep text contrast high on off-white; make flexible templates navigable.

## Borrow
- Use templates/examples to make flexible software concrete.
- Make AI features feel like workspace affordances, not magic glitter.
- Warm up productivity without lowering clarity.

## Avoid Copying
- Do not rely on charming illustration to cover unclear information architecture.
- Avoid turning every surface into a document if the product is actually transactional.
- Do not overuse beige/off-white until the UI becomes visually flat.
