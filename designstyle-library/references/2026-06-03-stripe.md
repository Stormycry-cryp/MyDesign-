# Style Reference: Stripe

## Essence
A product-led SaaS/fintech style that makes abstract infrastructure feel tangible through layered modules, crisp product fragments, and controlled color energy. The reusable idea is contrast: enterprise trust in the typography and grid, liveliness in gradients and animated product surfaces.

## When To Use
- Payment, infra, API, AI platform, or developer-product pages that must persuade several audiences at once.
- Landing pages where the offer is technical but the first screen still needs momentum and brand recall.
- Product narratives that can show real UI fragments, code snippets, partner logos, and metrics in one coherent system.

## When Not To Use
- Internal tools where gradient energy and marketing density would reduce scan speed.
- Early MVP pages without real product surfaces; fake dashboards make this style look hollow.
- Brands that need warmth, intimacy, craft, or editorial slowness more than platform confidence.

## Visual System
- Layout: Strong editorial grid with diagonal/layered hero staging; sections alternate between broad narrative bands and dense proof modules.
- Typography: Confident sans-serif hierarchy, short headline lines, compact technical captions, strong rhythm between display and UI-scale text.
- Color: Mostly neutral foundation with high-chroma gradient accents, blues, violets, greens, and warm highlights used as energy fields rather than decoration.
- Density: High information density, but grouped into precise modules; copy, metrics, UI previews, and logos are tightly choreographed.
- Shape: Rounded product panels, pill CTAs, browser-like modules, and soft clipped layers.
- Shadow/depth: Depth comes from overlapping planes, gradients, and subtle elevation rather than heavy card shadows.

## Assets
- Image style: Product UI composites, code fragments, transaction/payment surfaces, partner proof, abstract infrastructure visuals.
- Illustration/icon style: Minimal line icons and small glyphs; avoid whimsical illustration.
- Texture/pattern: Gradient meshes, faint diagonals, and luminous color washes.
- Likely sources or production method: Real product screenshots, design-system UI mocks, CSS gradients, WebGL/canvas only if it supports the product metaphor.

## Motion
- Page transitions: Smooth section entrances; no theatrical route transitions needed.
- Micro-interactions: Hover states reveal links, shift panels, or emphasize CTA affordance.
- Scroll/entrance behavior: Layered hero objects and product modules can drift or reveal on scroll.
- Timing/easing: Medium-fast, confident, cubic ease-out; motion should feel like systems coming online.

## Interaction And Components
- Navigation: Multi-level product nav with grouped categories; enterprise trust depends on findability.
- Buttons/links: Primary CTA plus secondary technical link; icons/arrows clarify direction.
- Cards/sections: Feature cards work when they contain real product proof, not generic benefits.
- Forms/inputs: If present, should be minimal and high-trust, with clear validation.
- Feedback states: Product demos and calculators should show deterministic, data-like feedback.

## Implementation Notes
- CSS/layout primitives: CSS grid, absolute layered hero planes, gradient backgrounds, clamp-based container widths, sticky nav, responsive module stacks.
- Token ideas: Neutral text scale, accent gradient tokens, product-panel radius, high-contrast CTA tokens.
- Libraries or techniques: Framer Motion/GSAP for scroll reveal if needed; CSS gradients and transform layers are enough for most clones.
- Performance/accessibility concerns: Keep animated gradients lightweight; ensure contrast over colorful backgrounds; do not hide core copy in animation.

## Borrow
- Use real UI surfaces as the hero asset instead of stock art.
- Pair dense technical proof with generous macro spacing.
- Let color create momentum while type and grid carry trust.

## Avoid Copying
- Do not imitate Stripe's exact gradient palettes or payment UI motifs.
- Do not pack every section with decorative product fragments if the product has only one simple workflow.
- Avoid generic purple-blue AI gradients without a product-specific reason.
