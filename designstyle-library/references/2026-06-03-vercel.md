# Style Reference: Vercel

## Essence
A developer-platform style built on monochrome clarity, sharp type, technical diagrams, and product primitives that feel close to code. The reusable idea is to make complexity legible by refusing ornamental noise.

## When To Use
- Developer platforms, AI infrastructure, deployment tools, API products, docs sites, and technical dashboards.
- Interfaces where credibility comes from speed, reliability, architecture, and examples.
- Product pages that need to bridge marketing, docs, and console UI.

## When Not To Use
- Brand systems that need sensuality, warmth, handmade craft, or lifestyle storytelling.
- Entertainment, AVG, or cinematic pages where atmosphere is part of the product.
- Products with weak technical differentiation; monochrome minimalism exposes thin content.

## Visual System
- Layout: Clean centered grid, strong top nav, modular feature bands, code-adjacent components, lots of white/black contrast.
- Typography: Geist-like sans/mono pairing; short declarative headings; labels and code snippets are first-class text.
- Color: Black, white, grays; accent color appears through product badges, status, or partner visuals rather than broad palettes.
- Density: Medium; pages feel scannable with deliberate sectioning and compact technical examples.
- Shape: Small radii, squared technical containers, precise badges.
- Shadow/depth: Minimal; use borders, background contrast, and subtle elevation.

## Assets
- Image style: Product console fragments, code blocks, architecture diagrams, deploy/status visuals, customer proof.
- Illustration/icon style: Geometric monochrome icons; simple SVG diagrams.
- Texture/pattern: Grid lines, terminal surfaces, sparse gradients only for depth.
- Likely sources or production method: Real dashboard screenshots, MDX/docs components, SVG diagrams, design-system icon set.

## Motion
- Page transitions: Fast and nearly invisible.
- Micro-interactions: Hover borders, command/search overlays, tabbed code examples, animated status/progress.
- Scroll/entrance behavior: Simple fades or reveals; content should remain immediately inspectable.
- Timing/easing: Snappy 100-180ms for UI, 200-320ms for content reveals.

## Interaction And Components
- Navigation: Docs/product/templates/customers split must be highly findable.
- Buttons/links: Monochrome CTA hierarchy with clear icon direction.
- Cards/sections: Technical cards should include actual examples or metrics.
- Forms/inputs: Search, command, auth, and deploy flows need keyboard-first behavior.
- Feedback states: Build status, deployment progress, errors, and logs are core aesthetic material.

- Inference: the style is strongly tokenized around Vercel's own design system, with docs/product components sharing the same primitives.
- Limit: exact component source is not public from this inspection.

## Implementation Notes
- CSS/layout primitives: Tokenized monochrome system, MDX components, CSS grid, sticky nav, code block components, border-based cards.
- Token ideas: `geist-black`, `geist-white`, `gray-100..1000`, `radius-small`, `mono-caption`.
- Libraries or techniques: Next.js/MDX, syntax highlighting, accessible dialogs/menus, minimal motion library.
- Performance/accessibility concerns: Monochrome still needs hierarchy; avoid low-contrast gray text overload.

## Borrow
- Make docs, examples, and product UI feel like one system.
- Use monochrome to focus attention on content and technical proof.
- Let errors/status/logs become designed components.

## Avoid Copying
- Do not use empty black-and-white minimalism when content lacks technical substance.
- Avoid overusing triangular/logo-like motifs that read as brand imitation.
- Do not remove warmth from onboarding flows that need reassurance.
